Usage metrics API flags telemetry and version gaps

GitHub Blog Changelog

GitHub's Copilot usage metrics API now includes per-user fields indicating whether client telemetry was received and whether each user's IDE or Copilot extension meets minimum supported versions. Daily counts of affected users appear in enterprise and organization reports, helping admins identify and fix telemetry or version gaps without opening support tickets.

GitHub Copilot 用量指标 API 新增了用户级字段，能直接看出谁没上报客户端遥测数据、谁的 IDE 或插件版本低于最低要求。企业和管理员报告里还会给出每日受影响用户数，方便管理员主动排查问题，不用再开支持工单。

  • New per-user fields: client_telemetry_present and usage_metrics_requirements (met/unmet/unknown per IDE and extension).
  • Daily counts missing_client_telemetry_user_count and below_usage_metrics_minimum_user_count appear in enterprise and organization reports.
  • Users without telemetry still count as active but lack detailed metrics like lines of code and feature/model breakdowns.
💡 Why it matters: Developers and admins can now pinpoint telemetry and version issues directly in Copilot metrics, improving data quality and reducing troubleshooting overhead.
🇨🇳 开发者和管理员可以直接在 Copilot 指标中定位遥测和版本问题，提升数据质量并减少排障成本。

Usage metrics API adds code review details and addressed rate

GitHub Blog Changelog

GitHub's Copilot usage metrics API now includes a new copilot_code_review object on each repos-1-day row, reporting how many Copilot code review comments developers addressed and how many Copilot-reviewed pull requests merged without a subsequent human change request. This enables tracking of an addressed rate per repository, broken down by severity, review tier, comment type, and customization.

GitHub 的 Copilot 使用指标 API 新增了代码审查反馈的跟踪能力：现在可以查看每个仓库中 Copilot 代码审查评论被开发者采纳的比例（即“已处理率”），以及 Copilot 审查过的 PR 在合并后是否还有人要求修改。这些数据还能按严重程度、审查层级、评论类型和自定义配置细分，帮团队评估 Copilot 审查的实际效果。

  • New copilot_code_review object on each repos-1-day row reports total_comments_evaluated and total_comments_addressed, enabling an addressed rate per repository.
  • Counts are broken down by severity, review tier, comment type, and customization (e.g., custom instructions, skills, MCP servers).
  • total_merged_no_human_change_request_after_review tracks merged PRs reviewed by Copilot with no later human change request.
💡 Why it matters: Developers and AI practitioners can now quantitatively measure the effectiveness of Copilot code review and the impact of customizations like instructions and MCP servers, enabling data-driven optimization of their AI-assisted review workflows.
🇨🇳 开发者和 AI 从业者现在可以量化评估 Copilot 代码审查的效果，以及自定义指令、MCP 服务器等配置带来的影响，从而数据驱动地优化 AI 辅助审查流程。
