Push attribution for commits in limited public preview

GitHub Blog Changelog

GitHub has introduced push attribution in limited public preview, durably recording the authenticated user who pushed each commit and exposing that identity in the UI and API alongside author and committer fields. A new repository rule, 'Committer must match pusher,' blocks pushes where committer metadata doesn't match a verified email of the authenticated pusher, closing a commit identity spoofing path. The feature is currently available to GitHub Enterprise customers via account team request.

GitHub 推出了「推送归属」功能（限量公开预览），现在会持久记录每个 commit 的实际推送者身份，并在界面和 API 中与 author、committer 字段一起展示。新增的仓库规则「Committer must match pusher」可以拦截 committer 元数据与推送者已验证邮箱不匹配的推送，堵住了伪造提交身份的漏洞。目前该功能面向 GitHub Enterprise 客户开放，需联系客户团队申请。

  • GitHub durably records the authenticated pusher identity for every commit, independent of author/committer metadata strings.
  • New repository rule 'Committer must match pusher' blocks pushes where committer metadata doesn't match a verified email of the authenticated pusher.
  • Pusher identity is visible in the UI and API wherever commits are shown, aiding security investigations.
💡 Why it matters: This gives security teams a trustworthy, authenticated identity trail for commits, making it harder for attackers with compromised low-privilege accounts to forge commits and bypass review policies.
🇨🇳 这为安全团队提供了可信的、经过认证的提交身份追踪，使攻击者更难利用被盗的低权限账户伪造提交并绕过审查策略。
