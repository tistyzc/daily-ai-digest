Restricting npm bypass-2FA granular access tokens

GitHub Blog Changelog

npm granular access tokens (GATs) configured to bypass 2FA can no longer perform sensitive account, org, and package management actions, which now require an interactive 2FA challenge. This change closes a major credential-based attack surface on the registry, affecting only npm GATs, not GitHub tokens. By January 2027, 2FA-bypass tokens will also lose direct publish capability, pushing users toward trusted publishing (OIDC) or staged publishing.

npm 的细粒度访问令牌（GAT）如果配置了绕过 2FA，将不能再执行敏感操作（如创建/删除令牌、修改包权限、管理组织成员等），这些操作现在必须通过交互式 2FA 验证。这是 npm 注册表安全的一次重要收紧，只影响 npm GAT，不影响 GitHub 的其他令牌。到 2027 年 1 月，绕过 2FA 的令牌还会失去直接发布权限，建议开发者尽早迁移到可信发布（OIDC）或分阶段发布流程。

  • npm GATs with 2FA bypass can no longer perform sensitive account, org, or package management actions; these now require interactive 2FA.
  • The change only affects npm granular access tokens, not GitHub PATs, GitHub App tokens, or GITHUB_TOKEN.
  • By January 2027, 2FA-bypass tokens will lose direct publish; users should adopt trusted publishing (OIDC) or staged publishing.
💡 Why it matters: This reduces the risk of account takeover via leaked tokens, forcing developers to adopt more secure publishing workflows and interactive 2FA for sensitive operations.
