Turning GLM-5.3-Flash into a Jev-like decision model

Hacker News

A team found a way to give standard LLMs like GLM-5.3-Flash Jev-like decision-making properties by crafting prompts so the first output token directly answers the question, enabling a decision in a single forward pass. Benchmarked on vLLM against Jev and Laya, their setup matches Jev in accuracy and speed, substantially beats Laya, but costs several times more per decision than Jev. Unlike Jev, it also supports vision inputs.

有人发现了一种让 GLM-5.3-Flash 这类通用大模型具备 Jev 式决策能力的方法：通过精心设计提示词，让模型的第一个输出 token 就直接给出答案，从而只需一次前向推理就能完成决策。在 vLLM 上的实测显示，这套方案在准确率和速度上与 Jev 持平，明显优于 Laya，但单次决策成本比 Jev 高出好几倍；作为补偿，它还支持视觉输入。

  • Prompt engineering makes the first output token the decision, enabling single forward-pass inference
  • Setup matches Jev in accuracy and speed and substantially outperforms Laya
  • Cost per decision is several times higher than Jev
💡 Why it matters: Developers can turn off-the-shelf LLMs into low-latency decision models without training a custom model, trading higher per-decision cost for flexibility and multimodal support.
🇨🇳 开发者无需训练专用模型，就能把现成大模型改造成低延迟决策模型，代价是单次成本更高，换来的是灵活性和多模态能力。

Usage metrics API adds pull request review stages

GitHub Blog Changelog 🔴 Factual

GitHub's Copilot usage metrics API now breaks down pull request review time into three stages: ready-to-first-review, first-to-final-review, and final-review-to-merge, with median and 90th percentile values per repository per day. The new pull_request_review_times array only counts human reviews, excluding Copilot and bot reviews, and data builds forward from the release date with no backfill.

GitHub 的 Copilot 用量指标 API 现在能把 PR 的评审耗时拆成三个阶段：待评审到首次评审、首次到最终评审、最终评审到合并，并给出中位数和 P90 两个数值。注意这个新数组只统计人类评审，Copilot 和机器人的评审不算数，而且数据从发布当天开始累积，不回溯历史。

  • New pull_request_review_times array on each repos-1-day row reports median and p90 minutes for three review stages: ready-to-first-review, first-to-final-review, and final-review-to-merge.
  • Only human reviews are timed; Copilot code review, bots, and author self-reviews are excluded, so total_merged in this array is usually lower than pull_requests.total_merged.
  • No backfill: data builds forward from the release date, and PRs ready for review before September 21, 2026 are excluded from this section.
💡 Why it matters: Developers and engineering managers can now pinpoint exactly where PRs stall—waiting for a first look, stuck in review back-and-forth, or approved but unmerged—and use the p90 alongside the median to spot outlier PRs driving delays.
🇨🇳 开发者和工程管理者现在能精确定位 PR 卡在哪个环节——是没人看、评审来回扯皮，还是批了没合并，还能用 P90 和中位数对比找出拖后腿的少数慢 PR。
